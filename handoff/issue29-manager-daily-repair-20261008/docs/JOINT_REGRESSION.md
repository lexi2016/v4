# Issue #29 / #28 共享候选联合回归

以下是 Luna Max 在同一隔离合成候选上运行的最小行为验收范围。本轮没有执行这些 Mac 联合测试，也没有启动服务、采集或正式计划；所有项目当前均为 `NOT_RUN_IN_THIS_TASK`。现有原测试优先复用，新增测试仅用于尚无覆盖的已确认风险。

## 输入与证据要求

- 固定候选身份：实际现役前像、合入的 #28/#29 diff、最终源清单和解释器。所有用例应引用同一合成候选，不能把不同根分别 PASS 拼成一次全局 PASS。
- 原 20261008 预选池：30 条盘前、149 条研究推荐合并去重后 A178，以及单独 HK100。使用本机既有产物、manifest、receipt 的隔离只读副本，记录其原 SHA、日期/市场、规范化有序代码列表的摘要及逐来源引用。当前远端交接没有完整原产物，不可仅按计数造一份样本宣称原数据回归已过。
- 公告固定产品：记录 analysis 与 workspace 对应的 run_id、产品路径/SHA、公告日期对、原判断状态和来源。33/54/75 仅适用于原观测产品；不得把数量写进通用业务规则。
- 数据无变化的前后比较应使用同一输入 SHA；差异只允许来自预期修复。后续数据自然变化时按新产品身份解释，不能用旧期望计数否定新结果。
- 仅用于分页、超时和负向校验的合成 fixture 必须单独标注 `SYNTHETIC_ENGINEERING_TEST`，不作为真实行情、资格或自然运行证明。

## 接续验收与状态

1. 先由模块作者运行相关定向测试，再由集成 owner 对同一个组合候选运行 J1–J10 的适用用例。缺本机原 fixture、完整源码或已接受差异时记录具体 `NOT_RUN` 原因，不合成通过。
2. 独立 Reviewer 检查实际命令、原输入身份、输出摘要、失败日志与 patch。若仅离线行为通过，`BEHAVIOR_VERIFIED` 的 scope 必须写“隔离固定输入”，不能写成现役 API/UI 验收。
3. 发布冻结期只交候选。解除冻结后的部署、真实 API、普通页面重载各自另给证据。自然时段必须读原调度触发、原owner实际执行、持久化产品与页面所读run的连续记录。
4. 手动、离线、回看、补跑、canary与自然运行分别标记；自然证据未观察为 `NATURAL_SLOT_UNVERIFIED`，不能以未来06:30时刻、disabled binding或HTTP200代替。

建议每个用例只存以下必要脱敏证据：候选源清单SHA、用例ID、命令/解释器、fixture清单SHA、目标日/市场、run及产品摘要、代码集合摘要、关键断言、结果/未执行原因。原始行情、完整计划、账户数据及完整live配置留本机，不上传。
