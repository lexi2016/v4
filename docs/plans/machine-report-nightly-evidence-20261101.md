# 研报夜间研究 → 决策台能力提升 · 完整方案（R2 修订版）

状态：**未实施**（本文只是方案，代码、开关、服务均未改动）
日期：2026-11-01
修订：R2 —— 依据独立审查意见修正 7 处实质问题

---

## 0. 一页结论

把本地 Qwen 研报作为**一路独立来源**，在夜间窗口批量分析，产出带完整时间链的证据，次日接进研报决策台已有的证据管道。

**但有三件事必须先做，否则方案不成立**：
1. 让"机器来源"成为一等来源身份（当前会被归一成 `manual`）；
2. 让 `available_at` 真正贯穿产物与回读（当前 `ResearchItem` 没有该字段）；
3. 用**代表混合队列**实测成功交付速率（不是拿短文档成功批次外推）。

## 1. 现状（实测）

### 1.1 数据量

| 对象 | 数量 | 状态 |
|---|---|---|
| 知识星球目录 PDF（`学习/知识星球/<日期>`） | 1,083 份，中位 1.5 MB | 6 个日期目录 |
| v35 入库 PDF | 6,050 份，20 GB | **停在 2026-10-27 23:00** |
| 已由 Qwen 分析 | 186 份 receipt → 101 份可展示卡片 | 覆盖 10/13–10/16 |
| 覆盖率 | **101/6,050 ≈ 1.67%**；**101/1,083 ≈ 9.33%** | 两个口径分别记录 |

### 1.2 性能（27 个真实批次）

| 场景 | 实测 |
|---|---|
| 短文档全成功批次 | 22–35 秒/篇 |
| **代表混合批次（142 篇，含失败）** | **47.8 秒/篇** |
| 长文档 + 源修复 | 170–1,500 秒/篇 |
| 失败率 | 65/186 ≈ 35% |

按 47.8 秒/篇推算：6.5 小时窗口约 **490 份**；1,083 份约需 **14.4 小时**，**超过两个夜间窗口**。
以上只是推算，**不代表成功交付速率**——必须以"每小时成功且验收合格的唯一文档数"为准，P0 阶段实测。

### 1.3 四个断点

1. 采集停摆：入库停在 10/27。
2. 分析覆盖不足：见 1.1 两个口径。
3. 两套数据不相交：10/16 决策台主线 2 只；同日研报**实体提及** 236 只。
   **注意**：236 是实体提及口径，与"主线 2 只"（经评分与池桥接的产物）不是同一量纲，**不得据此断言主线会增强**。
4. 部署基线漂移：本地 `zsxq_pdf_ingestion.py` 3,858 行 vs 部署版 2,591 行；`pdf_queue_night_admission()` 只存在于部署版。

### 1.4 Qwen 产出质量（101 份实测）

- 数字落地率：中位 99%，均值 96%；可核验 79 份全部 ≥70%
- 结构：风险段 93%、来源归属 86%、预测/事实分离 82%、页码引用 64%
- 空文档（水印页）会被明确判定"无实质内容"，不虚构
- 短板：仅 15% 输出股票代码；平均 2,078 字（摘要级）；22% 源文本为空

**结论口径**：可作证据来源；**不能**作独立结论。历史 PDF 试验出现过"完整返回但语义验收失败"，因此本版必须给出事实、主体、引用、时态四类质量证据，而不是只看能否返回。

## 2. 目标与非目标

**目标**
- 机器研报成为决策台证据链中一路**可追溯、可去重、可回滚**的独立来源。
- 夜间批量产出，次日可用。

**非目标**
- 不改 BUY gate、不产生信号、不出现买卖点。
- 不新建面板/生产器/数据库。
- **不在本方案内宣称"主线质量会提高"**——那是另行验收的结论。

**验收必须分开**：
- A. 来源可追溯（每条证据能回到原文页码）
- B. 覆盖增加（新增多少可核验证据）
- C. 运行稳定（夜间连续运行、可续跑）
- D. **主线质量提高**（单独定义、单独验收，不得由 A–C 推导）

## 4. 必须先修的四处合同缺口（R2 新增）

### 4.1 来源身份（原方案错误）

- 现状：`normalize_source_type` 对未登记值**一律归为 `manual`**（`domains/research_hourly.py:209`）。
- 现状：`source_confidence` 只接受 `LOW/MEDIUM/HIGH`，其它值被按等级映射覆盖（`:453`）。
- **必须**：把 `machine_report` 登记进 `SOURCE_TYPES`，并新增"来源族"字段（`ORIGINAL` / `MACHINE_DERIVED`），使机器来源在产物中**独立可辨**。
- **禁止**：用适配器塞字段冒充接通。

### 4.2 时间链（原方案不足）

- 现状：`ResearchItem` 无 `available_at` 字段。
- **必须**明确：字段定义、写入层、过滤层、产物持久化、回读路径。
- `available_at` **不等于**批次完成时间，至少应覆盖：原文取得 → 分析完成 → 验证 → 正式发布，取其中最后一个。
- 名称表版本、LinkProbability 语料指纹必须**一并冻结**，否则历史模拟会用到后来信息。
- **今天分析的 10/16 研报只能作为事后模拟，不得回填成 10/16 当时可用的证据。**

### 4.3 评分语义（原方案错误）

- 现状：每条 L2 加 15 分，另按不同 `source_type` 数 ×5 加分（`:554`）。
- 后果：三条机器证据即可贡献 **50 分**；同一原始研报经原渠道与机器渠道进入还会重复计数。
- **必须**：
  - 按**原始文档 SHA + 原始来源 + 具体事实**三级去重；
  - 区分"独立佐证"与"重复转述"（同一原文派生的机器摘要不得被计为独立来源）；
  - 明确机器来源是否参与 `source_type` 的 5 分项。

### 4.4 阈值（原方案写错）

- 现行冻结规则：`total ≥ 3` 且 `LinkProbability ≤ 0.2`（**含等号**）。
- 方案 R1 误写为 `< 0.2`，必须改为复用既有实现，不得另立阈值。

## 5. 冻结规则（修订）

| 项 | 规则 |
|---|---|
| 来源身份 | `source_type=machine_report` + `source_family=MACHINE_DERIVED`（需登记枚举） |
| 置信度 | 不使用 `MACHINE` 伪值；由等级映射，且机器来源不得映射为 HIGH |
| 证据等级 | 上限 L2；**未通过事实/实体/时间校验的证据不得默认获得 L2** |
| 单股证据条数 | `min(独立文档数, 3)`，且独立按 §4.3 判定 |
| 去重 | 原始 SHA + 原始来源 + 事实级；跨渠道重复只计一次 |
| 通用词 | 复用既有 `total ≥ 3 且 lp ≤ 0.2` |
| 单日上限 | 可配置；**必须区分**：分析文档数 / 成功文档数 / raw_item 数 / 单股证据数；并定义排序、延期、队列老化 |
| 开关 | 默认关闭；**关闭不等于撤销已物化影响**（见 §7） |
| 回滚 | 版本化输入集 + 发布指针 + 旧产物恢复路径 |

## 6. 实施阶段（修订）

### P0 · 基线与冻结样本（前置，不含任何管道改动）

- 在**独立源码分支**归并现役必要差异（含 `pdf_queue_night_admission`），固定 manifest/SHA 后构建候选；**不长期直接修改部署目录**。
- 盘点 `research_pool_bridge` 及 CSV 的下游消费方（从 P4 提前到此处）。
- 用冻结样本做只读模拟：固定日期、固定名称表版本、固定语料指纹。
- **输出**：新增股票对照表；事实/主体/引用/时态四类质量证据；代表混合队列的成功交付速率。
- **验收**：可复现；无券商名/通用词/无来源股票；速率以"成功且合格"计。

### P1 · 夜间批次 runner

- 队列 + checkpoint + 续跑 + 上限（明确单位）。
- 窗口复用部署版 `pdf_queue_night_admission`（02:00–08:30），与 OCR 队列错峰需实测。
- **验收**：整夜可中断续跑；失败不污染已完成产物。

### P2 · 来源接入（含 §4 四项合同修复）

- 登记 `machine_report`、来源族、时间链、去重与评分边界。
- 单日 canary，开关仅对一天生效。
- **验收**：与 P0 模拟逐项一致；产物中机器来源独立可辨。

### P3 · off/on 对比

- **同一冻结数据与同一 cutoff** 下对比；给出 Top10 重合度、新增数、重复计数为 0 的证明。
- **验收**：差异可解释，无未登记来源。

### P4 · 全量启用 + 调度注册

- 依赖 P0 的消费方清单。
- **验收**：连续 3 天自然运行。

### P5 · 前端

- 仅加来源徽章与覆盖度计数，结构不变。

## 7. 回滚（修订）

关闭环境变量**不会**撤销已写入 `research_items → stock_daily → CSV/bridge` 的产物。因此：

- 输入集合版本化（manifest + SHA），产物带版本指针；
- 保留旧产物与恢复路径，回滚 = 切指针 + 重放，而不是改开关；
- off/on 对比必须在同一冻结数据上做；
- 任何一轮失败只受控回退本批，不污染基线。
