## 4. 新提交协议：必须了解的存储变化

### 4.1 权威结果与兼容旧数据

新结果的权威记录是：

```text
<manager-state>/.commits/<YYYYMMDD>/<input_identity>.json
```

一份提交文档携带 `schema_version`、日期、输入身份、revision、product、终态 jobs、对应 receipts 和整体 SHA-256。发布使用同目录临时文件、文件 fsync、原子替换和目录 fsync。回执兼容镜像单独存在不代表提交成立。

旧 `products/`、`jobs/`、`receipts/` 文件可以按既有身份合同读取，但 GET 不迁移、不改名、不覆盖原件。**新生成的产品以 `.commits` 为准，不能只扫描旧 `products/` 目录判断新版本是否产出。** 包内主要调用已走 `ManagerResearchStore`；包外直接读取旧磁盘结构的消费者未被验证。

`replace_product()` 仍用于显式旧格式替换；对已经提交的新格式结果，会抛出 `COMMITTED_UPDATE_REQUIRES_NEW_ATTEMPT`，要求走新的尝试与 `commit_result()`，不允许绕过终态和取消约束。

### 4.2 状态与竞争顺序

```text
新 generation + attempt → QUEUED → RUNNING → READY / PARTIAL_WITH_ROWS /
                                            CANNOT_CONFIRM / FAILED
                         └───────────────→ CANCELLED
```

准入、取消和提交按同一输入键互斥。如果取消先取得线性化点，后续发布拒绝；如果提交已经成功，取消返回实际终态，而不是虚构 CANCELLED。旧 generation 的进度、失败处理和清理不得覆盖新尝试。

任务失败时可以仍保留上次完整缓存用于观察，但不能把失败尝试伪装成新的成功。旧格式数据仅有身份与安全校验，不应作为新格式提交完整性的证明。

### 4.3 事件合并

事件采集在锁外执行；提交时读取最新 product，仅通过既有催化投影合并事件字段。回归验证了“采集期间财务更新”不会被旧财务对象覆盖。没有增加多次外呼或在锁内等待来源。

## 5. 安全语义与兼容性裁决

全局安全守卫仍拒绝任意交易动作及放行旗。经理原 UI 把研究建议标签叫做 `action`，因此使用一个限定合同的**验证投影**：只认研究-only schema/作用域和固定标签枚举，不持久化改名，也不跳过嵌套旗。`action` 与 `research_label` 冲突直接拒绝，防止投影覆盖隐藏数据。任意 observation 中的 BUY action 仍不允许。

五个 Store 的业务验证仍留在各自公开入口；通用 I/O 只承担安全路径、编码后的字节发布及同步。扩大回归曾发现把通用业务 action 校验放入基类 writer 会误伤其他合法研究合同，已撤销这种错误耦合，同时保留 Native import/catalog 的严格校验。

路径检查拒绝原有 Windows 盘符形式，即便当前在 POSIX 上运行，也不把 `C:outside` 当作合法相对文件名。新 I/O 未对 Windows 悄悄降级：不支持的环境失败关闭。macOS 配置应使用没有软链接祖先的真实路径，例如必要时使用 `/private/var/...`，而不是通过 `/var` 软链接写入。

## 6. 新增预算及其实际含义

| 边界 | 本次缺省值 | 超限行为 |
|---|---:|---|
| HKEX 响应体 | 32 MiB | Content-Length 和实际读入双重检查，超限拒绝 |
| HTTP 跳转 | 最多 5 次、同目标重复上限 1 | 下一跳发送前检查，不允许先请求再判断 |
| PDF 输入 | 32 MiB | 不启动超大输入提取 |
| PDF 页数 | 500 页 | 不返回静默截断的“完整”事实 |
| PDF 提取文本 | 8,000,000 字符 | 超限失败，不冒充完整解析 |
| PDF 协作式时间预算 | 30 秒 | 页边界检查；不能强制打断单次卡死的提取调用 |
| 经理待处理任务 | 16 | 超限不继续无限准入；来源线程已有四 worker 上限 |
| 受限文件读取 | 64 MiB | 超大存储对象失败关闭；不是全库内存限制 |

这些默认值是工程保护值，不是从实际行情/公告样本校准得到的容量证明。特别是线程池数量有界，**不等于**已取得硬总时长或硬内存保证。

## 8. 使用与回滚

1. 解压完整代码包到新的工作目录，不覆盖正在运行的 release。保留原 ZIP 和原状态目录备份。
2. 使用新的 `V35_DATA_ROOT` 与 `V4_MANAGER_RESEARCH_STATE_ROOT` 沙箱。共享阶段数据根单独指定，作为只读来源。
3. 启动器默认 `shared`：必须提供 `--stage-selection-root` 或 `V35_STAGE_CENTER_SELECTION_ROOT`，命令行优先。只有明确需要本地阶段生产者时，才使用 `--stage-mode local`；local 与共享根不能同时指定。
4. 新旧 writer 不允许共用一个状态根。未知/空/损坏旧锁不自动按年龄删除；确认旧进程退出及证据备份后再做显式恢复。
5. 以新 API/Store 读取提交结果，不以旧目录是否新增文件作为唯一验收。对包外消费者、macOS/Python3.14、浏览器、真实来源与运行图先补验收。
6. 回滚是停止新进程、切回原源码和原状态根；不能仅反向应用代码补丁，却继续让旧版本读写新状态目录。不删除提交记录来伪装回滚。

补丁只应对**上传快照对应的隔离副本**先做检查：

```bash
git apply --check /path/to/v4_app-optimization-20260911.patch
# 检查成功后才在隔离副本应用：
git apply /path/to/v4_app-optimization-20260911.patch
```

本包附完整源码，使用完整包不需要先应用补丁。历史证据哈希不批量更新；正式接入前，需要对数值边界规则 `finite_zero_v2` 单独冻结差异和版本。
