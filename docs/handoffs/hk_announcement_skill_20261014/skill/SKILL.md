# 近24小时港股公告研究

用户要求“过去24小时”时，以当前时刻冻结 `[起点,终点]`，使用 `Asia/Hong_Kong`（UTC+8）并写出精确时间；窗口左开右闭。开始前先盘点可复用的同源缓存或既有权威读取路径。新读取限于用户请求范围和已有访问路径；不新建 scraper、采集器或 producer，不把一次性试验脚本当成通用工具。遇到验证码、权限拒绝或来源不可用时停止并保留 `CANNOT_CONFIRM`，不绕过。

分别检查以下三条智通栏目线，并为每条记录命中的缓存/读取证据、时间范围和页数；未覆盖的栏目明确写为缺口：

- 港股公告：`announcement.html?data_type=1&page=N`
- 港股市场：`content/hkstock.html?data_type=1&page=N`
- 港股研究：`research.html?data_type=1&page=N`

锁定的 RSSHub 路由及其限制见 [references/source-coverage.md](references/source-coverage.md)。它的 RSS 时间取自 `create_time`，且只请求第 1 页；不能据此单独证明完整的24小时覆盖。按可核实的发布时间筛窗口；分别保留发布时间、创建时间、更新时间、底层事件时间和采集时间。缺少可核实发布时间时标记待核，不能用新闻时间代替交易日或事件日。

去重先用 article ID，再合并同一公司同一底层事件；跨栏目转载只计一个事件，可保留多个类别和链接。逐条审阅财务与业绩、订单/合同、批文/商业化、临床或科研未来催化、公司回购、大股东或机构实际增持、券商研究观点。不要按近期涨幅或热度筛掉前瞻线索。把正向、负向和混合影响都写出；证据不足时用“待核”或“不优先”并说明原因。重要性按证据和影响机制定性判断，不自造权重、阈值或固定 TopN。易混判例见 [references/semantic-cases.md](references/semantic-cases.md)。

每条值得展示或待核的线索写明：股票代码与名称；港股通匹配状态、名单日期和来源（未知则待核）；类别；发布时间与事件/交易时间；原始证据链接；新增事实；影响机制，并把推断标明；金额/币种及其条件（有则写）；未来催化和不确定性；“关注、待核或不优先”的理由。把公告事实与分析推断分开。正文或原始披露表未核实，要在该条明示。

结尾简述三条来源各自覆盖状态、观察到的去重事件数、分页/正文/验证页缺口，并按事件数汇总。无结束信号、遇到非单调分页后提前停止、达到页数预算或存在读取错误时，完整性为 `CANNOT_CONFIRM`；缺失不等于零，也不宣称穷尽市场公告。所有输出保持 `RESEARCH_ONLY=true`、`production_allowed=false`、`buy_gate_updated=false`、`orders_sent=false`，不自动接入评分、选股或订单。
