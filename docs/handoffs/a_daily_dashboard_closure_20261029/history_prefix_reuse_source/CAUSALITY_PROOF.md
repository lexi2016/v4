# Exact consumed-field prefix causality (source-only)

All proof claims are bound to STATIC_FEASIBILITY.json's exact engine/formula/core/census hashes. Core signals reads seven buy branches plus two levels (membership uses only the two levels); census reads the same nine, OHLCV and prefix dates. The nine roots have31 transitive assignments and only CLOSE/HIGH/LOW/VOL raw formula inputs. No total-length/asof/drawing field enters this closure.

Pinned engine proof: binary/unary operators act pointwise. REF enforces nonnegative integer k and uses i-k. MA/HHV/LLV/COUNT windows end at i; COUNT(k=0) uses only[:i+1]. EMA/SMA state seeds/advances from current or previous values; BARSLAST records only prior/current true indices and preserves unknown reset; CROSS uses current and i-1. Thus for the same exact first bar and every identical prefix bar, each root at i is independent of later bars, including its warmup/None. Runtime AST walking admits only these pinned current/past functions and OHLCV/DRAWNULL raw inputs, rejects unknown/cyclic/length-sensitive dependencies. CURRBARSCOUNT has different prefix/asof behavior in this engine; the path conservatively excludes it rather than claiming all51/22 are interchangeable.

Census is **not** prefix-invariant as a full-date summary: suffix arrays and selected anchors must be rebuilt within the requested prefix. The change always calls the original census on cropped rows at each historical cutoff; it never slices or reuses today's summary. Only original OHLCV plus the nine proven values are borrowed. Drawings and unused fields are absent from borrowed rows, which are immutable copies.

Binding before reuse: exact four source hashes/bytes via the existing SourceContext cached SHA guard, config bytes/digest/ref, stock, target/cutoff, generation/full identity (including basis/snapshot/input), qualification digest, identical start/date sequence, and exact prefix raw-byte digest. Prefix digests are constructed in one forward scan and checked on the actual supplied prefix. The full result must have original formula/mode/51/22/date identity. No tail-only warmup, market ordinal, synthetic bar, calendar replacement or unknown-fill is allowed.

Normal daily/default behavior is unchanged. Only compute_stock(..., history_dates=..., reuse_history_prefix=True) opts in; otherwise legacy prefix recomputation remains. Historical qualification continues to be current-generation descriptive replay, historical_PIT=false and maximum DIRECTION_ONLY. Raw G4 lookup is still called per cutoff, including missing/UNKNOWN.
