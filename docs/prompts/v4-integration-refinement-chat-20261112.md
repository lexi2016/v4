## 2. 用户真正要解决的事

用户认为V4模块过多，衔接不清，选股时要自己切换页面、对日期、找同一只股票、比较公式名单、查研究与富途进度。希望V4更方便地支持每天选股和研究判断。

实际问题包括：

- 原公式、v1.9.2和预选池人数不同，但缺少同口径、逐股的差异说明。
- Stage7缺合格结果时，独立有效的复盘池曾被连带阻断。本轮只历史回补了11月12日复盘池62只；Stage7因研究完成凭证缺失及原快照时间校验不通过保留缺失，不能拿事后结果补绿。
- 同一只股票的量价、研报、基本面、公告、行业、盘中结果和复盘分散。
- “基础数据已更新、已选股、网页已显示、富途已同步、研究已返回、已接入”混在一起，用户不知道当天究竟完成哪一步。
- canonical、现役角色、历史修复和候选版本需要明确归属，整合不能静默丢掉现有能力。

## 3. 请审查并细化初步思路

日常主导航拟收敛为三个入口：

1. **今日选股**：完整候选、入选理由、来源筛选、公式差异、我的重点观察、盘中变化、交付进度。
2. **个股研究**：同一股票的量价结构、关键K、基本面、产业卡点、业绩兑现、公告/重大事项、控制人意愿能力与债务质押、反证及缺口。
3. **复盘验证**：同批候选、用户关注、阶段结果、当日及D+2/D+5表现、漏选归因和流程失败。

盘前、盘中、收盘、次日准备是时间视图；任务与交付有固定状态入口。原公式、v1.9.2、研报、公众号、Stage7等保留为来源、独立策略判定或专业工具，按用户任务组织展示。请判断三入口是否合理，并给出依据，不要再叠一个平行“总工作台”。

完整候选在同一市场按证券去重展示，保留各来源、版本、原分数和时间。公式比较需同来源日和可比输入，展示共同入选、仅原公式、仅v1.9.2、未完成判断；不同输入或缺少条件明细必须明确，不猜原因，多来源重叠不直接等于高置信。

一只股票统一详情，复用原图、历史标签、评分与已合格研究。量价先判断前段建仓波/拉升波，检查已有大幅拉升、大阴线和结构破坏，再结合关键K和后续缩量；阶段判断不直接证明主力建仓。基本面/行业/重组线索要有事实和反证，未知概率不编成数字。

“重点关注、继续观察、待核实、暂不关注”是用户研究管理状态，不改模型资格或分数。关注股可关联已有阶段结果，未覆盖不自动当淘汰。历史冻结结论与事后快照/补选分开，后来的信息不反写盘前判断。

每天形成可追溯进度：基础数据 → 同版选股 → 完整名单和研究Prompt → 页面投影 → 富途 → 研究回包 → 校验接入。各项独立记录真实完成时间，不因研究未齐就清空有效候选。富途显示目标组日期、批次、应有/实有数量和实际回执；研究区分已收到、已校验、已导入、页面可见。

## 4. 必须保留的边界

- V4/8873是唯一研究用户入口和源码项目，复用原owner、已有数据、API、产物合同与完成事件，不建第二底板、平行producer或第二长期面板。
- A/HK独立日历、池和规则；观察日、候选来源日、行情时刻、研究材料可用时点分别保留。
- 所有合法可追溯A股候选可进入既有阶段链；缺失、空或partial子池只隔离坏来源，不全局阻断；200行分页不能截断真实选股输入。
- 各原模型、公式、分数、阈值和阶段排序保留。综合排序若要改变，另列研究假设、基线、评价和验收，不能直接把不同分数相加或承诺收益。
- UNKNOWN不填0，未执行不等于0只，旧名单加新行情不等于当天新选，历史回补不等于自然成功。
- 用户关注、研究文字不改BUY gate或订单。Vibe8910在替代验收前保留原样。
- 保留原始数据、已验结果、历史失败和其他任务工作区；旧入口或服务在替代验收前不擅自删除/停用；不机械合并所有历史分支或所有同名变体。
- 既有标签、缓存、资料与Drive ID复用，只补新增/变化/缺件；不为整合界面重算全部历史。外部操作按原授权，本轮只设计。
