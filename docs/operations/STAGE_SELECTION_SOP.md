## 4. 最小修复顺序

1. A/HK 异常隔离：一边失败、原文件 OSError、缺上下文时，另一边继续；不从共同异常路径一起退出。
2. 部分来源：有效可追溯部分可以继续；PARTIAL、来源完整性、完成/可用时间与缺口必须保留。
3. 幂等发布：复用原严格 CAS 的 EXPECTED_MISSING 恢复；同输入重试核代码、源回执、时间和 SHA，不能每次重新生成身份后当同一封存输入。
4. 完成证据：按原 owner 校验输入、出版和完整调度链；不得只摘取内层 SUCCEEDED，忽略外层或工作项 FAILED。缺有效证据走第1节降级，不编造完成回执。
5. 09:25 行情：保留真实 source_time、捕获区间和原 cutoff。原 snapshot 补读有界；原 TDX 查询次数、BJ 能力和交易权限不擅自扩展。
6. 候选封装：保持原 manifest 的完整条目 metadata。复用原 entry，再更新实际变更的 SHA/size，不能重建简化字典漏掉 kind=file。
7. 新清单必须被真实消费者接受：检查原 trusted_research_owner/_release_manifest，而不只是包内哈希、服务能启动或 /healthz。
8. 候选模拟/overlay 必须标明隔离验证；真实安装环境无 overlay 读回是上线后必要步骤。
9. 补采必须完成后续选股：复用原A评分、排序、Top10上限；禁止按候选顺序截取10条。最新研究来源无有效见证时，优先明确采用已验证且在快照前可用的既有上下文，并记录回退原因与实际source slot；确无合法上下文则明示NO_VERIFIED_RESEARCH_CONTEXT，研究源字段仍null，沿原纯引擎已有中性语义继续行情补选。不能改写as_of、trusted reader、原门禁或失败回执，不能把缺失上下文称为已认证。不为研究补选另造全量研究分值齐备门。

## 5. 发布与安全切换

- 先完成必要源码、针对性验证和冻结范围独审，避免把准备、源码、打包分别变成多轮审批。
- 每次实际动作重新核当前 owner、manifest、原 guard/锁 inode、accepted jobs、队列、PDF、原日更和健康子任务。
- 不停止健康任务，不为同范围阶段切换反复问一般授权；需要人类凭据时只要求本机认证，不读取密码。先完成同一批所有必要准备和真实候选消费者检查、确认人类可配合后再发一次有效认证请求；日常自动快照补采不触发这种服务换版认证。
- 仅更改 idle/calendar-only 服务时，优先使用已审核同 UID 的 idle→bootout→absent→精确 CAS→bootstrap→loaded 回读路径；确认无 PID、无在途任务、正确日历与原锁。
- 活跃常驻服务确需 next-spawn 保护时才使用对应受限控制和必要管理员认证；不把所有小修改都扩成 Main/API/collector/Stage 全切换。
- 不把 TCP 连接等同于在途查询；零累计字节的 idle preconnect 不是 SSE。只判断此次改动的真实依赖，不能用无关页面连接制造假阻断。
- 保留原日历 300 秒间隔及方案明确期限。过期方案、nonce、helper、CAS 一律不重放；下一空档更新必要参数，复用已有 PASS 并只核增量。
- UNKNOWN 先查真实状态/原 checkpoint，不盲重试 launchctl、重复 CAS、杀健康进程或补造“未执行”。
- 其他任务发布了新 API/页面时，刷新实际身份并保留它的成果。本次只修两个 Stage owner，就不回滚别人的 API。
- Main 换版要同步 Stage 的 research_owner_binding；调用源、图绑定和历史 evidence-only 引用不能相互冒充。
- API/Main与Stage依赖更新串行协调；切换前再次比对实际Main的app_root、release_id、manifest及loaded配置，漂移即停止尚未执行的旧批次并只重绑变化参数。current加最多两个显式历史pin，退窗不删除原来源或已发布历史产物。

## 6. 5073 只股票与原数据保护

- 5073 是原底板覆盖数，不等于每个阶段合法预选池应当有 5073 行。
- 只读消费已有候选池。保护原 Parquet、pointer、备份、历史失败与原 HK 结果；不重采全市场、不重算原底板。
- 保护证明复用原小文件 SHA、大文件 inode/dev/size/mtime、旧 HK index entry 和备份存在性；不为反复验收重哈希十几 GB 面板。
- 原定日更的合法新结果不能被强制回退成旧指针。
- 旧目录删除不是解除 launchd 配置的方法。先核加载配置、占用、依赖、回退与自然运行证据；只清理确定无用的本批临时项或已授权、无依赖的退役版本。
