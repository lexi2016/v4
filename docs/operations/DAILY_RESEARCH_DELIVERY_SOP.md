## 3. 研究面板完成后能否自动同步看板

已有接入：Main的`infrastructure/scheduling/executor_registry.py`原A执行器会续行原日包/原图物化及`complete_daily_derivatives`；`ops/research_panel_daily_product.py`在完成owner内更新日期索引、原图、score_action、v192_assets、statistics及`events/latest.json`，Top200另由`ops/research_panel_top200.py`续行。API和工作台消费同一正式日包根。

结论：完成事件到日包/看板投影已有集成路径，不必每次人工复制股票；但不保证上游失败后也有新日包，不保证每个附加模块无缺件，也不能把针对性测试当新版本的每日自然验收。既有研究资料可按reader的时点/主体合同复用；新的Chat研究仍要独立验收和接入。

当日验收按顺序执行：

1. 核D/O、当前Main/API/Stage身份及原任务状态；健康任务等待检查点，不重复启动。
2. 核D日producer receipt、selector/backtest、generation、input SHA；失败保留原错误。PARTIAL可有合法股票，但不能把整体PARTIAL换成READY。
3. 核正式`index.json`确实登记D，manifest/artifact同代、全名单去重及子池状态完整；不能拿latest旧日期替D。
4. 核原图、五分持股评分/有仓无仓建议、v1.9.2独立组、Top200、公司材料及行业二筛各自descriptor；未知不填0，不因一模块失败清空合法候选。
5. GET核日包、原图、公司材料和评分，按用户指定或默认3个代表检查页面，保留市场/来源或已知异常边界。通过即停，未抽样不称逐股验收。
6. 检查当前页收到事件/刷新后实际日期与数据，不以只写event文件代替浏览器更新。分开记录ARTIFACT/API/UI/NATURAL。

## 4. 富途、Chat与网盘

既有自动化ID为`17`，名称“每日17点选股交付”，当前ACTIVE、每日17:00触发，内部按A股交易日历跳过休市日。原提示词已包括分组顺延、完整当日表现、Chat提交、旧回包归档和兼容V4导入。2026-11-10晚间依用户新指令更新了原自动化17的容量轮换段；仍为每日17:00、ACTIVE、原目标聊天，没有新建或改时。

1. 齐备后冻结package_id、D/O、generation、完整symbol与名单SHA。检查既有交付回执/富途目标组/已发Chat，避免重复。
2. 富途先核总容量和证券身份，不新增备份；整批一个导入文件。容量不足时按用户2026-11-10明确授权，直接在客户端整组删除最早的日期自定义分组（本次为1029），不逐只清理。按真实观察日/既有回执判最早日期，不按组名字符串排序；删除后回读组目录及实际剩余容量，再续行原D/O/generation的新组。仅删除为本批腾位所需的最早日期组，不扩删其他组或自行改成跨组逐只删除。整组删除若仍未释放足够总容量，报告真实容量缺口。导入后回读完整集合、missing/extras、股票类型和非零ID，不能只看成功弹窗或截断名单。
3. 导出全名单`CANDIDATES.csv`、`DAILY_PERFORMANCE.csv`、`INPUT_MANIFEST.json`和START_HERE，保留组别。已有历史位置/关键K/建仓波标签直接复用，未知、破锚和缺图独列，不重新全历史计算。
4. 当日表现含真实价格日期/时刻/复权、涨跌、额/量及单位、量比明确分母、历史位置定义、行业二筛、基本面状态。D+2/D+5未成熟留空。美股session、日本/韩国各自时点分开，页面应展示实际涨跌与行业强弱，不能只给PARTIAL代码。
5. 网盘先查后传、相同内容复用原ID，只传缺失/增量。以成功回执、文件ID和链接作为上传完成；依2026-11-10用户规则，不例行重新下载/远端SHA回读。结果未知先查原目标/ID，不盲重传。
6. 用[固定研究提示词](DAILY_CHAT_RESEARCH_PROMPT.md)填入本批真实参数，复用旧基本面，只补新增/变化/缺件。未经填充的模板不是已生成的当日研究任务。
7. 通过内置浏览器在明确Chat会话提交一次，记录可持续URL、prompt SHA、附件或核验后的网盘链接、发送/回复状态。用户已授权后直接续行；登录/锁屏等真实阻断才求助。没有正式名单时不发送旧批冒充新批。
8. 对旧研究先收取成果、覆盖与缺件归档，再归档已结束会话；运行中的研究不取消/归档。已提交但未收取、已归档但未导入、已导入但UI未验收分别记。

## 5. 基本面、卡点与重组研究回包

研究必须包含：主营与利润来源、财务质量/增长与现金流、产业链卡点/替代难度/客户认证、业绩兑现条件、估值和反证；结合已有量价锚及最近已完成海外session做三个行业二筛。海外偏强不证明A股公司获益。

重大事项同时覆盖已公告事项与尚无具体公告的待核线索。重点穿透实控人及一致行动人/平台的整合、收购或出售意愿和执行能力，分实控人、持股平台、上市公司三层核债务、质押、到期、冻结、减持/转让及套现压力。未知个人债务不填0；高质押、放量或上涨均不能直接证明重组或违法。

“老鼠仓”方法研究区分重大事项前疑似信息先行与受托资金交易前的趋同交易；需要原监管/司法/研究证据、时间/账户链及反例。普通日线、席位、季度持仓不足以认定账户行为。无可校准样本时重组概率为UNKNOWN。当前事实与晚于D披露的新事实分开。

回包校验：全symbol机械覆盖/去重/缺失/多余、日期和批次身份、实际文件与来源；内容默认3个代表，失败只扩受影响原因。既有合格基本面和字段各自复用，缺件不抹去已验收内容。字段兼容才经现有owner、锁及CAS接入公司材料/行业二筛；不兼容记NOT_IMPORTED，不另建producer。接入后API和代表UI核回，评分建议继续沿原KB/量价规则，不让Chat基本面文字直接覆盖评分或BUY门。

每个阶段记录实际时间：PLANNED → STARTED → ARTIFACT_READY → VALIDATED → FUTU_VERIFIED / CHAT_SENT → CHAT_RETURN_RECEIVED → IMPORTED → API_VERIFIED → UI_VERIFIED；自然运行另设NATURAL_VERIFIED，阶段之间不可跳级。
