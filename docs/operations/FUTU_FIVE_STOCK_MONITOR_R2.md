# FUTU 五股实时监控 R2

任务：`FUTU_FIVE_STOCK_INTRADAY_MONITOR_R2`。本程序为独立前台 Python
进程，只读取本机 `127.0.0.1:11111` 的 `OpenQuoteContext` 行情，通过 macOS
静默系统通知提醒。固定点位来自 CHATGPT_MASTER 的 **2026-11-20** 指令。

`RESEARCH_ONLY=true`、`production_allowed=false`、`buy_gate_updated=false`、
`orders_sent=false`。程序不创建交易上下文，不读取账户，不修改主图、公式、自选股、
登录状态、调度器或任何研究面板。行情和去重状态仅存内存；标准输出是当前运行回执，
无行情历史文件、数据库、通知收集系统或额外网页。停止进程后去重内存消失，重启可能
再次提醒当日条件，重启前的路径不会被重建为真实先破后收。

## 启动和停止

使用本机已安装的环境，不需要重装：

```sh
cd /Users/lexi/.codex/worktrees/futu-five-stock-monitor-r2
export PANEL_PYTHON='/Users/lexi/Library/Application Support/com.lexi.v4.local/runtime/venvs/v3.5-mac/bin/python'
"$PANEL_PYTHON" -B -m ops.futu_five_stock_monitor_r2
```

终端保持打开，**Ctrl-C** 关闭本程序自己的行情连接。OpenD、富途客户端和其他服务
继续运行。本交付没有启动持续监控，也没有安装开机启动或计划任务。只有执行默认命令
后，本进程才持续监控。

先检查五股订阅和口径，**不弹窗**：

```sh
"$PANEL_PYTHON" -B -m ops.futu_five_stock_monitor_r2 --check
```

退出码：`0` 为五股当前均具备信号计算条件；`2` 为 `CANNOT_CONFIRM`（例如盘前、
休市、旧日期、权限未知、部分流订阅失败、日线不足或口径不一致）；`1` 为连接/查询
错误。JSON 回执包含每股五路订阅结果、代码和当前来源简称、固定名称、币种、
源日期/时间、QFQ 根数、当前 OHLC/股数校验、市场状态、权限及公式可用状态。
订阅成功不能独自证明实时权限或自然运行通过。连续交易窗内，`--check` 最多留
15 秒逐笔观察窗口；盘前/休市不等下个交易时段。即使返回 `2` 也会关闭本进程连接。

测试一条本地通知，**不连接行情**：

```sh
"$PANEL_PYTHON" -B -m ops.futu_five_stock_monitor_r2 --test-notification
```

该通知标题和内容明确含 `SIMULATION`，不是实盘触发。通知采用 `/usr/bin/osascript`
的固定脚本和 argv 传参，默认无声音。成功返回仅说明系统接受请求，不能证明屏幕已
显示。若看不到横幅：系统设置 → 通知 → 脚本编辑器 → 允许通知、选择横幅；检查
专注模式是否允许脚本编辑器，或由用户按需要临时关闭专注模式。本程序不自动改变
系统权限或专注模式。

## 数据和时序门

五股每只订阅 `QUOTE / K_1M / K_5M / K_DAY / TICKER`，A/HK 分组以隔离单市场
权限/报价失败，只消费这些代码。失败订阅每至少 30 秒有界重试，已成功的流不重复订阅。
连接复用现有 V4 `infrastructure/futu_quote_provider.py` 的本地只读工厂及代码映射。
本轮专用 OpenD 实时源不读取或物化研究面板。分钟推送可见但不假定推送复权类型；
实际日线和 5 分钟计算都显式拉取 `get_cur_kline(..., AuType.QFQ)`。

每股最多读取最近 300 根 QFQ 日线，含当日形成中 bar；至少 116 根才做全部含 REF
的公式（114 日均线及前两日引用）。窗口只在内存存在。对最新日线与同日 QUOTE
逐项比较代码、日期、open/high/low/close 和 volume，必须一致才计算。成交量直接
使用 SDK 股数，不按手放大或缩小。日线重复/乱序、缺值、OHLC 异常、日期不匹配、
实时与前复权当前锚点不匹配时，公式保持 `UNKNOWN`，不会把 raw 历史拼成 QFQ。

实时权限只使用 `get_user_info([UserInfoField.QOTRIGHT])` 中的 `cn_qot_right` 和
`hk_qot_right`，不打印 SDK 可能附带的身份字段。`BMP / NO / DELAYED` 禁止信号。
已安装 SDK 对 A 股可能返回 `N/A`；此时只有全部流订阅成功、收到 **TICKER push**
的 `push_data_type=REALTIME` 且时间新鲜，才可作为本次 A 股实时资格证据。
港股只接受 `type=AUTO_MATCH`；A 股当前 SDK 对正常成交可能标 `UNKNOWN / N/A`，
在已确证的 A 股连续交易窗中接受这两种及 `AUTO_MATCH`，仍拒绝明确的迟报、补录
成交等其他类型。拉取 `get_rt_ticker()` 的回放不能代替 push 证据，程序不使用它。
即使权限为 LV1/LV2，路径本身仍只认新鲜 REALTIME 逐笔。

`quote_authority_capable` 只表示当前权限/当日实时证据允许消费报价；
`realtime_confirmed` 还要求今日连续交易窗内新鲜报价。旧日 HK 报价即使 LV2 也不
标成实时已确认。新鲜 REALTIME 的权限事实单独按本日、本连接保存，午休或收盘
只重置路径，不抹掉这个事实；断线、权限变化/拒绝或源报价失败则使证据失效。
因此 CN 权限 N/A 时，仍能凭当天本连接观察过的真实成交、今日最终报价/同源日线、
SDK 收市状态做收盘确认；不要求 15:01 仍出现连续交易逐笔。

新鲜事件须在本日且距本机当前时刻 0–15 秒。OpenD 行情登录、服务器时钟（偏差
不超过 15 秒）和逐股市场状态每约 10 秒核对。A 股连续交易窗为 09:30–11:30、
13:00–15:00；港股为 09:30–12:00、13:00–16:00，且 SDK 必须同时确认
`MORNING / AFTERNOON`。午休、周末、休市、竞价、不明状态均不做盘中路径。
自然无成交导致数据不新鲜时也隔离，不用旧行情补造信号。

SDK 时间同时支持 `HH:mm:ss.mmm` 与 `HH:mm:ss:mmm`。首个有效实时逐笔只建立
路径基线；若它已经低于风险线，立即发当前失守 P0 并注明“先后路径UNKNOWN”，
不推断进入监控前的破位。之后必须实际观察到从点位
上方/等于点位跌到下方，再有更大 sequence 的实时逐笔回到点位，才发出
“盘中破位后收回｜承接观察”。记录首破时间/价格/sequence、最低价和收回时间。
同秒成交可按 sequence 排序。缓存包 `CACHE`、断线补包 `BYDISCONN`、延迟/异常
数据、午休/跨日、连接或权限变化、队列溢出均重置路径。内存去重保留同日已经发出
的事件，不跨断线猜测发生顺序。

5 分钟 K 在本机 SDK 实测为右端标签（09:35、09:40…）。仅处理具有后继 K 的
已闭合 bar；完整区间 `[time_key-5min, time_key]` 必须在收回之后、同一连续交易窗。
该 bar 最低与收盘都不低于点位才确认承接候选；最低或收盘低于点位发再次失守。
当前未完成 bar 和包含收回动作的部分区间不能冒充完整 5 分钟确认。因此确认可能
等到后继 bar 出现。已确认承接后再次逐笔跌破仍会发风险。

盘中公式提醒标记“盘中形成中”。日线收盘确认额外要求今日 bar 和同日最终时段报价，
A 股至少 15:01 且 SDK 为 `CLOSED / STIB_AFTER_HOURS_END`；港股至少 16:11、
SDK 为 `CLOSED` 且报价时间不早于 16:00，避免在收市竞价期间确认。状态或最终
时段证据不足则保持未知，不能拿旧日收盘当今日收盘。松原安全收盘 CLOSE<15.04
才标记“原锚正式失效”；原固定价位仍保留。

## 公式与通知含义

公式实现在 `formulas.py`，以原任务字面阈值独立计算：

* BBI 为 MA3/6/12/24 均值；白线为 EMA(EMA(CLOSE,10),10)；黄线为
  MA14/28/57/114 均值；MA60、9 日 RSV、SMA(RSV,3,1)、SMA(K,3,1)、J 均保留。
* B1：`BBI>白线 AND 白线>黄线 AND J<=13`。
* B2 A：`VOL>=昨日VOL` 独立量能语境；阳包阴单独辅助观察，不增加 J<55 硬门槛，
  不认证完整 B2。名称 `B2_1006_ORAL_CONTEXT`，P2。
* B2 B：`VOL>昨日VOL*1.20`，名称 `B2_151_VOLUME_CONTEXT`，仅独立量能语境，P2。
* B2 C：`COUNT(J<13,3)>0 AND VOL>MA(REF(VOL,1),4)*1.25 AND 今日涨幅>4
  AND J<70 AND 白线>黄线`，名称 `B2_USER_EXACT_CANDIDATE`，不新增 B1 前置。
* B3：`REF(J,2)<20 AND REF(VOL,1)>MA(REF(VOL,2),4)*1.15 AND 昨日涨幅>3
  AND 白线>黄线 AND 真突破`；真突破为 `今日涨幅>0 OR (今日涨幅>-3 AND
  (VOL/昨日VOL<0.6 OR VOL/昨日VOL>0.9))`。不额外要求昨日突破前高。
* 死叉严格要求当前白<黄且昨日白>黄；破前低为
  `CLOSE/MIN(REF(CLOSE,2),REF(LOW,1))<0.99`；昨日守线按向上缺口选择昨日高
  或 `MIN(LOW,REF(CLOSE,1))`，再用 `CLOSE<REF(昨日守线,1)`。三者 OR 才是
  卖点公式命中，并分别显示各分项。盘中不能标成日线收盘卖点。

EMA 与通达信 SMA 使用首个有效输入起算；MA 需要完整窗口。RSV 前 8 行未知，
分母为零不补值；递推开始后遇到缺值，后续递推也保持未知。本任务未认证与任何
富途主图显示逐点数值一致，原主图完全不写入。价格涨幅、量比和阈值比较使用十进制
数，保留 `>4`、`>3`、`<0.6`、`>0.9` 等严格边界。

P0 包含支撑失守、关键K破锚、再次失守和卖点风险；P1 仅完整用户原式候选、或
完整 5 分钟承接候选；P2 为价格/压力区/缩量回调/阳包阴等观察及 B2 两个独立语境。
每条含股票和代码、当前价格及币种、触发时间、类型、固定点位和基准日期、实际
条件、关键K状态与下一观察。公式通知带实际指标与量能数值。港股始终附
`HK_REFERENCE_ONLY`，A 股完整原式命中也不构成关键K、有效承接或完整结构买点
认证。所有候选均不自动下单或更新 BUY 门。

同日按股票/事件/点位去重，盘中候选与收盘确认分别记忆。日线形成中条件变回
不成立后再成立，也不会不断重复提醒。断线后只重建本进程连接和订阅，指数等待最多
30 秒，重置路径并保留同日去重。持续连接失败继续输出未知回执，用户可 Ctrl-C 停止。
常驻运行只在连续交易窗或收盘后首小时读取对应市场的日线/报价；其他时段保持行情
连接和轻量健康检查，不整夜反复拉五股 K 线或刷 UNKNOWN。`--check` 可检查历史对齐。
