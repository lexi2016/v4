# V4 旧研究面板迁移、退役与写入控制

V4 8873 提供唯一研究入口，由现有发布者维护当期选股与回测的配对代次。日常页面、选股、回测和导出均通过 V4 的现有 Reader 读当期代次。复现从同一入口按冻结代次读指定数据。同一字段的历史口径或生效日期不同，应随各自代次登记。A 股和港股各自保留市场合同。

## 已查明的写盘来源

- R28 补尾段只涉及 37 只证券、148 个新增键，仍输出约 1,706 万行的完整选股和回测表。六份早期修复选股表合计分配 46.48 GB。原有完整发布分支被局部维修复用，每次维修都沉淀了一个独立历史版本。
- 两版 Top200 的实际研究覆盖 197 只，各写了约 1,716 万行整表，每版在当期面板字段之外多 79 列。两版 KB 面板各多 107 列。早期研究脚本把基线和补充字段存成完整产物，存于各自运行目录。正式日更的保留策略只覆盖受管对象，无法按保留代数回收这些目录及明确保护的根。
- 日更历史曾发生单股检查点与正式历史重复落盘。既有隔离回放覆盖两个归档日，写入从 21.82 GB 降为 0.97 GB。这轮另查到生产者在请求分块布局时，对历史扩展、尾段修复、归档追加、同日修复四种模式静默切回整表写入。 [历史增量记录](2026-11-13-daily-history-delta.md) · [面板生产者](../../../ops/research_panel_qfq.py)

## 整合顺序与保留方式

先用 18 路径清单的编号、原 SHA-256、来源代次和消费者建立逐份绑定。每份登记角色、交易日、复权口径、规则版本、读取列和标的覆盖。复用 V4 现有配对发布清单和逻辑 Reader。通过流式对照确认一致的行列复用同一组块，增量保存新增列、修正行和已有事件引用。冻结旧版本的基线身份与原收据，原 SHA 继续表示原文件字节。 [配对发布](../../../ops/research_storage_pair.py) · [逻辑读取](../../../ops/research_panel_logical.py)

| --- | --- | --- |
| 首批试迁 | 17、18，Top200 两版 | 先复用已有 R4 精简投影及读回收据。收据覆盖 197 只、637,839 行，原名单 3 只继续标记数据未知。17 引用 18，复现需同时保留文件元数据里的 08 基线 SHA 与候选收据的 D222 配对来源身份。分别登记可复用投影、差异字段、事件和读回条件，逐份验证历史复现。 |
| 扩至 KB | 14、15，规则及动作两版 | 以冻结 D222 来源和原运行收据判定适用股票、日期和规则版本。两版各有 107 个额外字段，逐版保留有效增量，原规则、动作、成熟时点和未知值随版本读取。 |
| 收敛正式历史 | 10～12、16，11 月正式代次及 P5.14.3 | 11 是 11/06 登记原件，16 是同 SHA 的全克隆快照。复现入口可以先试改为通过冻结代次解析到 11，再验证 P5.14.3。两路径共享数据块，退役 16 的主要收益是减少重复路径。10、12 及其后续配对按历史代次接入。 |
| 收敛早期修复链 | 01～06，R28、920002、archive8 及历史候选 | 按原收据依赖拓扑接入，保存逐代的修正及精确恢复引用。同一截止日也须独立验证。03 的原候选收据缺失，保留原件并维持 `CANNOT_CONFIRM`。04 还被现役与回滚 API 绑定，随下一批验证并退役。 |

历史消费者有两种验收合同。按键和字段读取的消费者，逐批验证行键、版本、值、空值和事件一致，再切到 V4 逻辑读。对全文件 SHA 或原文件路径做强绑定的消费者，保留原件直到能从适用的归档位置读取同字节原件，或完成现有 Reader 的引用迁移并实际复现。归档需核恢复路径、原字节 SHA 和存储所有权。按字段复现的新产物应有自己的 SHA 和来源映射。

## 验收和删除动作

1. 先核已有投影的实际文件、manifest 和固定版本。在隔离条件下测试 Top200 读入口。逐项核对原 200 名单、197 只覆盖、3 只未知、行键和事件绑定。复用已有样本 `600809.SH`、`600187.SH`、`920156.BJ`，核页面和 API 的历史日期、字段值、缺失状态及事件。全文件或全版本引用仍按原收据机械验收。导入和验证均按标的、日段与字段流式读取。
2. 在现有发布协议中切换已验收的消费者引用。对应旧版、当期、精确回滚和失败恢复均能实读后才判断原路径的处置。在线消费者用适用的一次自然运行核对。切换失败时恢复原配对引用，保留失败记录。
3. 每份原件形成一条退役清单，列原路径、保留路径或逻辑代次、SHA、消费者验证、现役和回滚保护、失败 checkpoint、owner/lease、预计回收量。只有依赖清零且已获删除授权的原件进入逐路径删除，并记录释放量及替代读回。删除完成后以同一 Data 卷的分配量与可用字节复核，计入迁移新增的持久块。

初查的 148.84 GB 是 18 路径的分配量总和，含共享分配。唯一同 SHA 组 11 和 16 共用完整数据块，拆掉一个路径的预计数据回收为 0 GB。盘点时有 Data 卷快照，18 项测得独占字节为 0。当前直接可删 0 份。各批的净可回收量须等替代范围、共享块及快照状态确定后复测。现有冻结文件、引用和计划任务均按本轮计划保留。

## 本轮源码验收

基线为 `03e42c0c3129341ba013fdaf29ae087c3ae6c93a`。面板 adapter SHA-256 从 `038c6f66890c2b6c8654cfbaf0a8b0fc7cc9fc2bf68cb70060e76aaeb5896e75` 变为 `6347fe210c19689395c9e5301aa877da8070d1797ad42a8dade22f989c724844`。计算内核和原修复计算检查哈希保持一致。macOS 项目的 V4 Python 环境执行 `python -m pytest -q tests/test_delta_parallel_control.py`，14 项变更相关测试通过，独立复跑全文件共 22 项通过，基线已有的 1 项因缺少 `ops.research_panel_turnover` 无法运行。独立审查范围为 producer 写入控制，外层保留策略可能在调用前已进行预算预约。

现役代次兼容、集成、生产发布、API/UI、自然时段验收和旧表物理迁移均为 `NOT_RUN`。adapter 文件 SHA 进入代次及复权口径准入，切换前沿用现有发布清单和兼容核对，验证旧代次绑定、精确回滚及候选口径凭证。防止任意桌面脚本绕开 V4 尚需落实到已登记的接入入口和受管写入目录，本方案未修改系统权限或安装清理任务。
