## 修复执行顺序
1. **经理前后端合同先收口**：沿当前Manager候选只补BI-01/02，避免仅后端27项通过就宣布可用。由一个写入者统一改相关身份与消费者；先复现后最小补丁，原未变测试结果复用。BI-04先核精确reader身份，能同批修则同批完成。
2. **调度恢复与状态一次协调**：RT-01/02/03/04与RF-01涉及共享ledger/dispatcher，放在同一受控改动面，避免并行写同文件。先移植已有正确实现，再补丢失的子任务决策和真实状态。
3. **Stage原存储恢复**：BI-03按原RawStore/SelectionStore修，不新增并行store或producer。保留R4跨市场保全与205摘要修复，失败恢复不得重新消费授权或清零预算。
4. **超时取消结构**：RT-05先在隔离进程故障场景确认再改，复用1555已有专用预算能力。
5. **本机一次整合**：Work以实际解释器、依赖及目标文件SHA接续；对受影响路径独立复验，普通API与页面读取同一run。任何真实采集、恢复额度、部署仍按对应已有明确授权执行，不从审查文档推导新执行权限。
