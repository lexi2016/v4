# Isolated resonance binding patch R2

This is a delta and evidence package. It is not a self-contained installation or a deployed selection application. Upstream/vendor source snapshots and real market sample data are intentionally excluded.

Prerequisites: the exact local source files from `lexi2016/zge-trading` commit `8b9c68ffbd18f44aa2a56b24d3f6e9979c340bdf`, under `research/20261023/optimized/source`; an existing pandas/pyarrow Python runtime; and the local task layout referenced by the supplied tests. `ACQUISITION_AND_PATCH_MANIFEST.json` records original Git blob/SHA-256 identities and expected patched SHA-256 values. Keep original snapshots read-only. Verify the original hashes before applying `resonance_binding.patch` with ordinary `git apply --check` / `git apply` inside a separate isolated copy of the fixed source tree. Add the independently written `input_binding.py` at `modules/simulator/input_binding.py`. Verify the patched hashes afterward. No installer is supplied.

The patch forwards canonical, copied, cutoff-bound dictionaries to the unchanged native detector. Before any indicator evaluation, it validates a SHA-fixed manifest and the unique `(code, signal_asof, selection_date)` producer record, including expected window SHA, RAW basis, units, source binding SHA, and current source panel identity. Changing the data while retaining the manifest is rejected. `SignalScore.input_binding` is an explicit dataclass field, retained by `dataclasses.asdict`; the native enum verdict still uses its normal enum-aware JSON encoding.

The direct resonance caller uses its original prior-bar signal window and the context mapped to that signal date. Missing context is explicitly recorded as unavailable with NEUTRAL weighting. This verifies only the resonance input boundary and its direct caller. The full simulator's provider, market-context computation, execution/serialization exports, and V4 integration have not been certified or deployed.

The real three-symbol check uses local-only profile artifacts. They are not in this package. `prepare_real.py` consumes the SHA-bound local owner panel and produces a manifest plus sample window artifact; it is a finite three-code provenance profile, not a data producer or full-market scan. Its execution requires a fresh contract and registry START. `verify_real_r2.py CONTRACT.json` consumes those already frozen artifacts, exercises the actual unchanged strategy detector, and checks native explicit-window signal parity, 15 pre-detector rejection cases, future append invariance, no ambient SQL/provider calls, input immutability, and serialized provenance. It imports the original test dependency loader but does not execute the prior six synthetic fixtures or the offline selection main. The parent task's `offline_runner.py` is included solely because that existing loader contains the exact tested dependency-loading functions; its prior all-market selection entry is outside this patch acceptance.

Every new profile/test/review run must freeze current code/input/config identities and receive a new registry START. Existing local PASS receipts can be reused only with identical scope and hashes. The supplied slim receipt describes the executed local check; it does not authorize reruns or describe a newly installed application.

No B1/B2/B3/brick selection rule was changed. In particular, the user's B1 rule `J <= 13 AND BBI > white > yellow` remains a separate implementation requirement. This patch does not turn the native negative-J signals into that rule and does not validate selection quality or returns. No simulation/backtest, full-market re-selection, UI/API/service change, Windows connection, or market-data network request was performed in this binding verification. Research-only flags remain enabled.
