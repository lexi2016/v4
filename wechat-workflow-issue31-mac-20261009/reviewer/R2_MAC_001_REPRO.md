# R2-MAC-001 minimal reproductions

`reproduce_r2_mac_001.py` packages the already-run `article_body_binding` and
`article_body_promotion` snippets as a parameterized script. It does not edit
candidate files. The promotion fixture is temporary and removed on exit.

From the workspace root, run both repros against a candidate copy with:

```sh
python3 evidence/issue31_r2_mac_20261009/reviewer/reproduce_r2_mac_001.py \
  --candidate-scripts /path/to/candidate/scripts
```

The candidate copy contains `wechat_article_intake.py` at the same SHA-256 as
the collector used for the original binding repro (`de9499c2e049bcf6d3da5ea6375831aece5eb2374e338e057f04e60dfd0c6058`).
If the collector is kept separately, pass
`--collector-scripts /path/to/collector/scripts`. Use `--mode binding` or
`--mode promotion` to run only one snippet.

The existing output logs were generated by the original snippets, before this
packaging step:

- `article_body_binding_repro.log`: run with `--mode binding`; it prints that a
  text BODY with no manifest is accepted, the collector's one unique URL, and
  rejection of the duplicate-URL image-only BODY.
- `article_body_promotion_repro_rerun.log`: run with `--mode promotion`; it
  prints acceptance with `manifest_rows=0` and `identity_image_count=0` despite
  the BODY containing an image.

This file only makes the recorded repro logic portable; it was not executed
after packaging, per the review handoff.
